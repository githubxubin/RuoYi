# 执行效率与范围控制

质量门禁保持不变，但默认用最小证据通过门禁，不把所有可能检查都提前执行。

## 1. 先判断任务规模

满足任一条件时标记为大型任务：验收标准预计超过 7 条；编码任务预计超过 4 个；同时涉及数据库、权限、外部服务、前端页面中的至少 3 类；或预计新增/修改超过 20 个业务与测试文件。

大型任务在 G1 前先提出 2～3 个可独立验收的阶段，默认只实施第一阶段。用户明确要求一次完成全量范围后才能整体实施。阶段之间复用同一项目地图，不重复全量识别。

## 2. 只做真实并行

两个写入任务只有在没有前置依赖、共享契约已固定、文件不重叠、各自可独立验证且集成成本低于串行时才并行。若乙依赖甲本次才创建的表、接口或类型，必须按依赖串行。小任务默认一个写入 Agent加一个只读审查，不强制甲乙。

## 3. Orca 是唯一外层编排器

主控创建工作 Agent 时只使用 Orca 当前 `orchestration` 指南。禁止模型或 CLI 内置的 `Task`、`Explore`、后台 Agent、子 Agent及私有 worktree；禁止 Orca → CLI 主控 → CLI 内置 Agent 的嵌套编排。用户手动创建时，主控只输出任务单并等待。

## 4. 文档简洁且不重复

- 项目地图默认不超过 250 行；已有可信地图时只局部更新。
- `00`～`04` 每份默认不超过 120 行，工作 Agent 任务单默认不超过 100 行。
- 同一接口、数据契约或测试步骤只在一个文件完整定义，其他文档使用编号和相对链接引用。
- 大段命令输出、测试 XML 和日志只放 `evidence/`，报告记录命令、退出码、摘要和路径。
- 超出默认篇幅时在 `00-run-plan.md` 记录必要原因；不得为了填模板扩写或重复代码签名。

## 5. 分层验证，不重复运行

1. 工作 Agent：最小定向单测或编译一次；失败时只重跑失败目标。
2. 主控集成：受影响模块测试一次，再执行必要的全工程编译一次。
3. 审查修复：只重跑被修复影响的用例；定向通过后才扩大范围。
4. 验收：数据库、浏览器 E2E、真实外部 API、全量回归按风险和环境可用性执行。

已经通过且相关代码未变化的命令不得重复执行。缺少数据库、账号、浏览器或外部密钥时记录为阻塞，不在开发阶段等待、搭建或反复探测。优先沿用现有测试栈；新增或升级测试依赖必须作为单独 G1 决策。

## 6. 时间与失败预算

- 单个工作 Agent 连续 15 分钟没有可交付差异或证据时，返回主控说明阻塞，不自行扩大调查范围。
- 同一失败最多进行两轮“根因假设 → 最小修改 → 定向复测”；仍失败则停止并提交证据。
- Agent 中止、上下文压缩或工作树为空时，不自动完整重跑；主控先判断已有产物能否复用，并由用户决定是否重试大任务。
