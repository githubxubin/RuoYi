# 阿里三缺陷修复

用户只需输入问题本身：

```text
$ali3-fix 保存时返回 500
$ali3-fix TC-03
```

不要让用户填写任务目录、复现流程模板、报告清单或禁止事项。优先从当前仓库、活动任务和最近失败报告自动补齐上下文。

## 自动定位

1. 用户给出 TC、任务编号或错误证据时直接关联。
2. 否则检查当前差异、`docs/ai/runs/*/00-run-plan.md` 和最近的 `06-automation-test-report.md`，选择唯一活动失败。
3. 没有现成任务时自动建立一个最小缺陷任务目录和需求/回归 AC；不得因为缺少旧文档而跳过复现和证据。
4. 多个活动任务或失败都可能匹配时，只询问一个简短选择问题。

## 执行

1. 读取仓库规则、关联任务文档、[统一修复规则](../ali3-dev/references/bug-fix.md) 和 [交付证据规则](../ali3-dev/references/delivery-evidence.md)。
2. 先稳定复现并保存脱敏证据，再将根因归类为实现、测试、环境或需求问题；修改前写出根因结论。
3. 使用根因报告模板生成 `root-cause-report.md`，关联 AC/DEV/TC；只实施与根因一致的最小修复。
4. 增加或更新回归用例，重跑失败用例、受影响测试和必要冒烟；把修复版本、实际命令、退出码和逐 TC 结果写入测试报告。
5. 更新编码计划和交付追踪；同一根因假设连续三轮无进展时停止并提交证据和人工决策点。
6. 不自行创建 Agent；需要其他 Agent 时只输出任务单，由用户创建和选择模型。

未经明确授权不得提交、推送、合并、部署或操作生产/共享数据库。
