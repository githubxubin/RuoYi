# 阿里三代码审查

最短用法：

```text
$ali3-review
```

默认审查当前工作树差异，并自动关联当前活动任务。用户无需填写任务目录、审查清单和报告要求。

## 自动定位

1. 用户指定任务、分支或范围时按指定内容审查。
2. 否则使用当前 Git 差异，并从 `docs/ai/runs/` 中选择与变更文件和活动阶段匹配的唯一任务。
3. 多个任务都可能匹配时只询问一次任务编号；没有任务文档时仍可审查差异，但把追踪缺失列为发现或剩余风险。

## 执行

1. 读取仓库规则、相关 `01`～`06` 文档、[统一审查规则](../ali3-dev/references/review.md) 和 [交付证据规则](../ali3-dev/references/delivery-evidence.md)。
2. 保持业务代码只读，检查正确性、安全、失败处理、项目一致性、测试充分性和 AC→DEV→代码→TC→结果追踪。
3. 只报告可执行问题，按阻断、严重、一般分级，提供文件、行号、触发条件、影响和修复建议。
4. 在主控/集成工作树中生成或更新 `07-review-report.md`；在审查子工作树中只返回结构化发现，由主控归档。
5. 未经用户明确要求不得修改代码；阻断和严重问题未关闭时不得建议通过 G3。
