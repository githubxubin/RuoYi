# Orca 多智能体与工作树规则

## 角色模型

- **主控智能体**：澄清目标、拆任务、分配所有权、收集结果、执行门禁。
- **分析智能体**：只读调查模块、依赖、风险、测试和安全，可并行。
- **写入智能体**：在独立子工作树中实现一个边界清晰的任务。
- **审查智能体**：读取需求和代码差异独立审查，默认只读。

角色按任务创建，不为每个软件工程阶段单独创建智能体。主控建议能够产生有效并行的最少数量并生成任务单，然后询问用户选择“主控创建并调度”或“用户手动创建”。选择前不得调用 `worker-start`、`worktree create` 或 `agent launch`；选择主控模式后才可按确认配置或 Orca 默认配置启动。独立任务立即并行，存在依赖、共享契约未确定或文件所有权冲突时才串行。

这里的智能体还包括模型内置子 Agent、后台 Agent、`Task`/`Explore` Agent和只读 Agent；不得用非 Orca 委派绕过上述选择。老项目识别如需委派，先创建 `00-run-plan.md`，再询问“主控创建”“用户手动创建”或“主控独立识别”。

所有任务统一采用五环节：需求与任务计划 → 甲乙并行开发 → 集成与交叉审查 → 验收与修复 → 人工合并。老项目结构识别属于第 1 环节的条件活动，不单独扩展主流程。

## 启动前

1. Orca 智能体权限设为人工确认。
2. 读取目标仓库规则和实际测试命令。
3. 确认项目规则已经提交到当前工作树；缺少根目录 `AGENTS.md`、`docs/ai/project-rules.md` 或项目内 `.agents/skills/ali3-dev/SKILL.md` 时停止，不用全局副本兜底。
4. 首次编排前运行 `orca skills get orchestration --full`，以当前 Orca 说明为准。
5. 建立任务依赖图、文件所有权表和集成顺序。
6. 建立 `docs/ai/runs/<任务编号>/`，由主控唯一维护治理文档；工作智能体只返回证据，不同时编辑报告。
7. 将 Agent 启动方式、执行器、模型和推理强度记录到实施计划；用户未指定模型时记录 Orca 实际使用的默认值。

## 工作树策略

| 工作类型 | 位置 | 原因 |
|---|---|---|
| 搜索、影响分析、审查 | 当前工作树，可并行 | 不写共享状态 |
| 单模块独立实现 | 新子工作树 | 隔离代码差异和测试 |
| 多模块并行实现 | 每个写入智能体一个子工作树 | 避免互相覆盖 |
| 共享入口、配置、锁文件 | 唯一集成智能体 | 高冲突文件串行 |

禁止多个写入智能体修改同一文件。发现范围重叠时，主控智能体必须重新划分所有权或改为串行。

## 智能体任务单必须包含

- 目标与非目标。
- 允许修改的目录/文件及禁止范围。
- 输入依赖和验收标准。
- 必须运行的验证命令。
- 是否允许提交；默认不允许。
- 交付格式：改动摘要、文件、测试结果、风险和未完成项。
- 关联的 AC、DEV、TC 编号以及证据保存位置。

## 集成门禁

1. 每个写入智能体在自己的工作树完成定向验证。
2. 主控智能体检查代码差异是否越界，不接受无关重构。
3. 独立审查智能体检查正确性、安全、测试和项目规则。
4. 阻断和严重问题清零后，在集成工作树运行受影响测试和冒烟测试。
5. 由开发者决定是否提交、合并和推送。
6. 主控完成 AC→DEV→代码→TC→结果追踪矩阵，缺少执行证据不得建议通过门禁。

## 冲突与失败

- 智能体修改越界：拒收越界部分，重新下发更窄任务。
- 结果依赖另一任务：挂起写任务，先完成上游，不猜测接口。
- 同一问题三轮无进展：停止循环，汇总证据交人工决策。
- Orca 或模型不可用：降级为单智能体串行流程，保留门禁并明确记录降级。
