# 阿里三 AI 开发规范仓库

本仓库维护团队级技能包、规则和模板，不包含具体业务实现。

## 修改准则

1. 每次修改前读取本文件、`rules/global-rules.md` 和与改动相关的文件。
2. 规则保持项目无关，不写入 RuoYi 或其他练手项目的框架、路径和业务约定。
3. 优先修改现有规则，避免创建含义重叠的技能包。
4. 不复制 Orca 会变化的完整命令行参数；编排前以 `orca skills get orchestration --full` 获取当前说明。
5. 修改技能包后运行一次 `quick_validate.py`，不要反复执行相同检查。
6. 不存放接口密钥、数据库密码、内部令牌或客户数据。

## 成功标准

- 技能包可独立安装并通过校验。
- 规则同时适用于新项目和存量项目。
- 多智能体写操作有明确工作树与文件所有权。
- 阻断或严重问题未关闭时不得建议合并。
- 每次行为变更都有需求、实施、编码、测试、审查和交付产物，并可追踪 `AC → DEV → 代码 → TC → 结果`。
- 主控在首次创建工作 Agent 前必须询问用户选择“主控创建并调度”或“用户手动创建”；未选择前不得启动，选择结果写入实施计划。
- 统一入口 `ali3-dev` 与 `ali3-plan`、`ali3-implement`、`ali3-review`、`ali3-fix` 共享同一套规则和产物，不在专项 Skill 中复制或分叉治理标准。
